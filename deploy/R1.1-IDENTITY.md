# R1.1 local identity acceptance

This step is local only. Cloud continues serving the immutable R0 release. There is no public registration, organization invitation, model invocation or production identity rollout.

R1.1 VERIFIED after PR22/23; R1 is in progress, not released. Canonical plan: [R1.1 plan](../../项目文档/06-AgentScope重构专项/07-交付与验收/阶段/R1.1-身份会话与个人空间实施计划.md). Implementation/evidence: [OpenSpec archive](../openspec/changes/archive/2026-10-15-r1-1-identity-personal-space/verification.md).

## Isolated fixture

Use `deploy/scripts/identity-local.py prepare` to create only project `agentplatform-r11-local`, its dedicated volume/network, loopback PostgreSQL 15441 and gateway 18086. Credentials live in ignored `.cache/r11-local`, protected for the current operator. Unit/integration tests use `identity_test`; browser/application data uses `identity`. Never point destructive tests at the application or cloud database.

Run Maven Wrapper `verify` with `R11_TEST_JDBC_URL=jdbc:postgresql://127.0.0.1:15441/identity_test?connectTimeout=2&socketTimeout=5` and `R11_TEST_PASSWORD_FILE` pointing at the local postgres-password file. No credentials belong in shell arguments. Build frontend with locked pnpm scripts, then run fixture `build`, `migrate`, `grant`, `seed`, `start` in order. `seed` is only a randomized local test fixture, not a deployment default. For browser acceptance use `BASE_URL=http://127.0.0.1:18086`, `R11_IDENTITY=1`, `LOCAL_API_CONTAINER=agentplatform-r11-local-api-1` and `pnpm test:e2e`.

`test-identity-http.py` runs real restart and PG outage cases against this fixture only. Run it serially with browser/recovery tests. `stop` preserves local volumes and credentials; never use blanket prune or remove volumes.

## Operator boundary

`identity-ops` runs with `spring.main.web-application-type=none`. Actions: `bootstrap`, `create`, `disable`, `reset-password`. Provisioning requires explicit `--request-id=<UUID>` and `--username=<name>`; supply password by console or `--password-file=<private Linux file>`. Do not pass `--password`, log input, or use default credentials. Bootstrap is permanently single-use in DB. Retrying a request with a changed password is rejected by checking the existing Argon2 hash, not by storing a fast password fingerprint.

Runtime role has read-only user/space/membership/storage access and session/rate DML only. Offline operator credentials are separate and never mounted into API. Login/revocation coordinate with a shared transaction lock and recheck status/password before creating a session.

## Compatibility and release

V2 is additive. `pf.baseline_version=1` describes the existing runtime state baseline, not the current Flyway version. No V1 edits. Identity routes only exist under the explicit `identity-local` profile; cookies default to Secure, with a guarded localhost HTTP exception. Keep R0 baseline lock historical; the current additive HTTP contract has a separate R1.1 lock. New contract scope does not change R0 health/readiness, events or HC-1 semantics.

Rollback disables the identity profile, retains identity data and returns to the R0 application. Production tag/TLS decisions wait for the R1 release plan. R1.2 needs a separate approved Plan/OpenSpec.
