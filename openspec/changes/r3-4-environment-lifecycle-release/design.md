## Transaction and receipt implementation detail
V14 adds the protocol identity to the existing operation row: historical rows remain ENVIRONMENT_V2; newly admitted lifecycle rows use ENVIRONMENT_V3. Keep the V2 command wire record and signature canonicalization intact. Persist immutable physical creation identity on each V3 operation so a later generation cannot change historical command bytes. PREPARE/WAKE create a generation; SLEEP/DELETE target the old creation identity. Retry stores the failed original intent rather than translating every failure to PREPARE.

A pending lifecycle intent uses the existing operation ledger with a DRAINING admission phase and an environment pending-operation reference. It closes new environment-use/file-write admission before asking an existing sandbox use to cancel. It never advances the old use fence before that owner's precise stop barrier completes, and never cancels or removes an independent file helper. Activation runs under the same lock order, after file and sandbox physical owners are quiescent; only then does it advance the fence, freeze the physical target and publish its outbox. UNKNOWN without exact stop evidence remains blocked. This is a handoff within the existing ledger, not a second scheduler or an alternate execution route.

For V3 stop operations, immutable receipt revision1 proves physical stop and revision2 proves cleanup. Container removal happens only after revision1 commits. A transient response while cleanup is pending is RUNNING; the canonical stop fact is retained, capacity is not released, and query retries only exact cleanup. Removal proof requires the prior exact stop receipt plus observation of that precise container's absence, not a bare404. Failed cleanup is a durable fact with bounded retry metadata. Historical V2 receipt behavior remains readable without fabricating revision2.

RunnerReconciler uses the existing managed maintenance lifecycle and a bounded observation lease/CAS on the original operation. Read-only lookup of immutable accepted commands must not renew or bypass an expired execution lease. Observation can only inspect the original resource or project verified stored facts. A different runner requires the existing signed proof that the original runner stopped. Expiry alone never grants creation, wake, arbitrary stop or replay authority. Current generation/fence and receipt hashes are checked again when projecting. A revoked actor cannot cause new work; a trusted privilege-reducing stop/cleanup can finish the exact previously accepted scope.

The observation lease is30s, distinct from the old60s execution lease and covering the fixed15s HTTP bound. Reconciliation issues only GET. This never executes a fresh canary, creates a business environment, changes files/quota or calls prepare/stop. The verifier shares the existing64MiB helper admission and retains unresolved helper state. Committed stop facts allow exact cleanup. No committed result means BLOCKED/UNKNOWN remains retained. Observation never changes the original owner, execution lease, generation or fence; projection uses a separate observer/revision CAS and rechecks scope, current authorization and stored receipt hash before commit.
