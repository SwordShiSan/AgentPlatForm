# Design
Approved plan: R1.3 2026-10-17, base ae211d9. Local only; existing phase and new step branch.
V4 adds personal preference revision, current USER credential pointer, sanitized audit facts and snapshot extension. Existing V3 ciphertext and PLATFORM grants remain the credential authority. Preferences default Flash/PLATFORM; explicit task values override preferences; platform constraints always win.
Keep POST /conversations without initialTask compatible. With initialTask, create and submit inside a single JDBC transaction and return the conversation plus accepted task. Reuse exact-body idempotency before resolving mutable defaults.
GET/PATCH /me/preferences uses ETag/If-Match. GET /effective-config and /tasks/{id}/configuration never return secrets. USER DeepSeek PUT/DELETE uses If-Match and a current-record revision; replacement revokes old identity without rebinding queued tasks. API encryption service receives transient secret input, never logs it or exposes ciphertext; master key is a readonly secret. Worker performs per-call live authorization and cancellation convergence.
Model selection applies only to future tasks, no runtime hot switching. Flash/Pro use official HTTPS with thinking disabled; prices versioned at admission. Existing context/output limits, single slot and UNKNOWN semantics stay unchanged.
Browser sessionStorage holds actor/space-scoped nonsecret drafts and pending idempotency body; Pinia owns UI state, Query owns server resources. Keys only live in the password input until request completion/unmount; never in caches or evidence.
Resource total <=2887MiB; >=768MiB host reserve. Reuse local R1.2 protected meter/data, no reset of old UNKNOWN holds; build and resource tests serial. Recovery uses additive DB changes and previous accepted images, no cloud operations.

Preserve the existing broker hostname in a protected local identity file before recreation so its persistent node directory is reused.
