# Decisions
Use ApprovalResumeService + AgentScopeConfirmationAdapter, Repository→typed Mapper/PO/XML, existing TransactionTemplate/AMQP. V17 extends interaction kind/decision and checkpoint phase and adds immutable tool_approval_binding/consumption; no second interaction authority.
Public task WAITING_INPUT is retained. Strict phase pairs: TOOL_APPROVAL↔WAITING_APPROVAL; PLAN_APPROVAL/QUESTION↔WAITING_INPUT. Full round and intent precede ASK; checkpoint retains ASKING; stop receipt precedes slot release. No DB transaction waits for provider/HTTP.
Restore uses original call from canonical ledger; answer transaction saves answer/resume/outbox only. Checkpoint verify/copy precedes operation changes. Policy/SDK entry/startTool all recheck; a valid once ticket only satisfies ASK, not hard DENY, Plan, unavailable capabilities or stale scope. startTool consumes once and starts original operation atomically with original lock order.
DENY uses a separate durable result boundary; no startTool and no side effect. SDK-generated denials must be observed by middleware, canonical observations include DENIED. Already successful reads return original observation. Unknown effects never replay; if no compatible safe checkpoint exists, block.
Approvals expire24h; stale binding permits DENY/cancel only. An approved binding stale at execution cannot run. If revoked actor prevents restoration, use existing controlled terminal cleanup rather than forcing SDK/content writes.
One BUSINESS per round, no mixed CONTROL; full list persists then reject unsupported batch before execution. R4.3 uses protected typed deterministic tool to force ASK, no global enabling of production capabilities.

# Least-privilege integration clarification (2026-10-27)
Actual browser integration found that the API may read only existing public tool-operation metadata, not call_json/result_json. Approval projection/answer validation must use a typed metadata-only Mapper and narrowly granted identity/hash/status columns; toolName comes from the server-generated interaction payload. Worker recovery keeps its private full-call access. No V17 checksum repair or broad grant is permitted.
The local workspace fixture exposes metadata/listing only. Its API profile must explicitly disable workspace lifecycle background relays rather than obtain workspace_capacity write privileges. Add an opt-out workspace lifecycle property (default enabled, unchanged production), disabled only in the R4.3 fixture. Runtime identity changes require rebuilding the candidate and rerunning affected functional checks; keep earlier successful and failed evidence separately.
