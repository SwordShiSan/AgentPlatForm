# Design

Chat uploads are owned by actor and space before conversation creation and are backed by private immutable assets, not a fabricated workspace. Existing file versions remain pinned by fileId/versionId. First task creation binds ordered attachments, immutable source and extraction hashes, configuration, reservation and outbox atomically; changed request content cannot reuse an idempotency key. Each access and physical call rechecks current authorization.

Asset work uses transactional outbox, RabbitMQ confirm, durable claim before ACK, signed runner, bounded renderer, validated output and exact stop receipt before publication. Distinct typed FILE_VERSION and CHAT_ATTACHMENT identities must have valid foreign keys; processing purpose is PREVIEW or TEXT_EXTRACT. Unknown stop or result retains the original slot/reservation and is reconciled without replay. Text extraction uses private S3 outputs with a 2MiB UTF-8 limit; no OCR, macros, network, external links or nested attachments. Existing preview protocol remains compatible.

The existing asset-processing ports and lifecycle implementations are reused for both purposes; repositories and physical command envelopes select the explicit purpose and typed source. Independent extraction tables remain authoritative for extraction jobs. Shared lifecycle code does not create a synthetic preview, workspace, file-version or chat-task identity. Source authorization must branch on the typed source, and a nullable workspace is accepted only by asset-processing signature paths; workspace management signatures still require a real workspace.

Context policy freezes model window, task window, output and reserve limits per task and bundle. Input, history, attachment text, tools and observations are counted together. New calls reserve estimated input plus safety and output rather than a full window; actual usage settles against the original reservation and day bucket. Legacy records and old checkpoints remain unchanged. State and checkpoint envelopes are bounded separately and validated before SDK persistence; no silent truncation or summarization.

Vue Query owns server state and Pinia UI/drafts. File, preview, artifact and chat views share immutable versions; a file reference gives no workspace tool privilege. Storage is projected from existing object and quota facts; file trash reuses existing lifecycle. Use lazy paginated virtualized navigation and session-scoped drafts. Changes use existing session, Origin, CSRF and authorization checks.

Release uses an explicit R5 profile and identical locally verified immutable images. During maintenance, user writes remain disabled and a consistent pre-migration snapshot is retained. R4 cannot safely consume V19 tombstone data; rollback to R4 uses the matching pre-upgrade snapshot only before user writes reopen. Never replace new production writes with the old snapshot.

The production renderer staging root is exactly `/srv/agentplatform/previews`, as already enforced by the accepted runtime policy; a release-folder path is not an additional permitted root. The first release attempt exposed an incorrect operator configuration and did not start a model request. R4 was restored with matching pre-upgrade database fingerprints and unchanged container/image/policy/UUID facts.

When restoring the original XFS image, unmounting may release its loop association. After verifying the exact original image hash/UUID, reattach only its recorded unassigned loop device (or validate an existing association to the same image), then remount with project quota. Do not change the original UUID or borrow another assigned device. Preserve both the original failure and restoration failure trace. These are release-tool corrections; application images, V21, codecs and public behavior are unchanged, so affected deployment checks replace a new whole application regression.

Production asset delivery retains the existing `mq_publisher` and `mq_execution` roles in `/agentplatform`. Extend their existing expressions only with the exact `ap.commands.v1`, `ap.asset.v1` and `ap.asset-extract.v1` resources required for declarations, bindings, publishing and consumption. Preserve other roles and credentials; do not grant wildcard/admin access. Persist the same expressions in the mounted definitions file and broker state so a broker restart cannot revert the correction. Verify both asset consumers before declaring release startup complete. A PENDING original outbox is allowed to deliver after permission repair; it is not recreated or run via a database fallback.

Production topology ownership: retained ap.asset.v1 is quorum whereas default framework declaration is classic. Preserve queue type/messages; versioned operator imports the exact extraction queue/binding alongside retained definitions, verifies consumers, and sets spring.rabbitmq.dynamic=false only for this production API/worker profile. Framework publishing/manual ACK remain unchanged. Do not delete/recreate existing queues or relax broker equivalence. Maintenance watchdog may be extended once to a recorded bounded deadline while writes remain closed and no rollback is active; no unconditional disable.
