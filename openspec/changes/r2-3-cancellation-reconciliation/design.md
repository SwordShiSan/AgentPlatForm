# Design
CancellationApplicationService coordinates commands; ExecutionControl tracks one attempt's SDK/provider/write/timer termination; ReconciliationService handles proven-stopped facts. Domain/API ports use Java CompletionStage, not SDK/Reactor types. AgentRun.cancel, Reactor disposal and JDK HTTP shutdown are reused. Do not treat Future.cancel as stop evidence. Preserve codec1 and old fixtures; change execution-control runtime bundle identity, drain old attempts, no hot restore.
## Transactions
Lock global slot→conversation→task/dispatch→attempt→calls/ledger. Cancel is monotonic and idempotent. QUEUED cancels atomically; RUNNING first sets cancel_requested, prevents calls/retries/text/round/CAS, then waits at most5s for SDK/provider/callback/writer/timer quiescence. Known unstarted/settled calls→CANCELLED; unknown remote result/usage→BLOCKED/UNKNOWN with RECONCILING holds. Terminal success winning the lock remains successful. Specialized terminal accounting may settle known usage after cancellation but never publish late content. Unconfirmed stop keeps the slot, rejects new execution and ceases renewal; trusted host stop proof plus expired lease is required. DB loss fails closed.
## Persistence
V8 task_cancellation records first actor/command/time/attempt/generation/fence; task remains authoritative. execution_stop_receipt binds exact owner/attempt/fence and local quiescence or existing host proof. model_call_reconciliation is immutable, space scoped, records command ID, expected revision, decision, evidence reference/hash, operator and before/after accounting; model_call.reconciliation_revision CAS. No business JDBC.
## Operator and HTTP
Protected evidence files and command IDs; KEEP_UNKNOWN preserves holds, CONFIRMED_NOT_EXECUTED needs unsent ledger or supplier evidence, CONFIRMED_USAGE needs matching identity/tokens/frozen price and reservation bounds. Missing/oversized usage stays unresolved. No duplicate settlement/refund or reversal of settled facts. All resolved cancelled tasks→CANCELLED, other interrupted tasks→FAILED; never autoqueue a started call. Existing safe convergence of already-committed final rounds remains.
POST cancel empty body/202/session/Origin/CSRF/idempotency stays compatible. GET /api/v1/tasks/{id}/reconciliation exposes stable stop stage, confirmed stop, unresolved count, call accounting/revision and advice only; no evidence contents/paths or credentials. Reuse existing state/message/usage events, update task version in the same transaction. Live identity/space checks include administrators.
## Vue
Query owns projection, Pinia UI only. Show stopping/unconfirmed/unknown/cancelled, partial and diagnostic IDs, no self-service reconciliation/retry. New independent task allowed only after local stop and slot release; explicitly indicate unknown round not included in successful-history context. Preserve SSE/generation/keyboard/themes/responsiveness.

API512/workers512x2/PG320/MQ512/Redis64/gateway32/fixture64MiB; total2528, max2887, reserve768, no swap expansion. Build/runtime serial. Detect active Docker context, no engine reset. Stop fixture profile explicitly. Prior V7 image compatibility on additiveV8 with collector policy unchanged; rollback never erases cancellation or accounting facts. Cloud unchanged.

Accounting detail: V8 also records model_call.provider_kind (REAL/DETERMINISTIC/LEGACY_UNKNOWN) when a physical call starts, so acceptance-meter and business-budget settlements cannot be confused. Historical rows remain LEGACY_UNKNOWN and are never guessed or reset; terminal resolution requiring an unknown meter provenance remains blocked. No new external integration.
