# Design

## Accepted baseline and framework ownership
Base main ff16819fec83c5eb27bb936a41552df61032d24b; phase synced by fast-forward before step creation. Java21/Boot4.0.8/AgentScope2.0.4/docker-java3.7.1 and existing Nimbus/Spring AMQP/MyBatis remain locked. No extra Agent loop or JDBC executor.

App owns environment prepare/read/retry/idle-stop/reconciliation; domain pure Java EnvironmentRepository/SandboxRuntime/FileAccess ports; infrastructure typed DAO/PO/XML and docker-java adapters; app packages XML and short TransactionTemplate operations; trigger thin controllers; frontend generated clients/Query with scoped keys.

## Lifecycle and transactions
Storage READY is independent of NOT_CREATED/PREPARING/READY/STOPPED/ERROR/BLOCKED environment. GET absent environment has revision0 and never creates a row. POST empty object requires workspace storage READY, If-Match environment revision and Idempotency-Key. Same key/body returns original stable operation; conflicting body409. Only explicit FAILED/NOT_STARTED accepts retry. STOPPED can prepare a new generation only after durable exact stop and no outstanding use.

V11 adds workspace_environment, environment_operation/outbox/inbox/idempotency, runner environment command/receipt, singleton sandbox capacity slot, exclusive environment_use and stop receipt. Composite space/workspace/environment constraints, unique command and operation, generation/fence/revision/hash checks. Additive widening of workspace.environment_state CHECK mirrors committed environment state; initial migration leaves existing workspaces NOT_CREATED. Fixed lock order slot→workspace→environment/operation→command/use/receipt. DB time60s lease/10s renewal; live actor authorization and owner/gen/fence rechecked before commit. No remote I/O in transactions. Single active sandbox slot retains unknown/stopping owners; expiry does not prove stopped.

Spring AMQP confirmed mandatory publications and committed claim before manual ACK, concurrency/prefetch1. Existing lifecycle factory/pattern reused; separate versioned environment routing queue avoids decoding v1 as v2. Worker invokes one signed POST, then only signed GET for the same command. Idle/revoke sweeps persist STOP commands through outbox; no DB direct execution fallback. Existing business task slot remains1, not replaced by this resource slot.

## Runner protocol and durable effects
Separate internal /internal/environment-operations endpoints and ENVIRONMENT_V2 envelopes bind method/path/raw body hash, kind, environment generation, fixed policy/image identity, actor/workspace/operation/command/owner/fence/deadline. Existing Nimbus RS256 keys remain separate and immutable. Binding only gains exact allowlisted new paths; old v1 paths/semantics preserved. Result signed with command/result hash/revision. Runner role can access only required environment facts plus existing authorize function, not chat/key/SDK state.

Create intent is committed before Docker create. Container name/labels include exact environment UUID/generation/command and image/policy hash. Existing physical intent is inspected and never blindly restarted. CREATED-before-start, STARTED-before-receipt and missing/unreachable daemon remain independently observable; uncertain effects retain BLOCKED/slot. Only definite pre-effect rejection can return ERROR and free unused slot. Physical deletion follows committed stop receipt.

## Runtime policy and file bridge
Only fixed configured runtime runsc and officially pinned20261005.0 systrap; validate daemon runtime path/runtimeArgs and binary identity through trusted bounded attestation, image/config/inspect, never dmesg. API/worker have no Docker socket, runner has no public port. Sandbox UID/GID10001, readonly root, cap ALL dropped, no-new-privileges, network none, no devices/socket/secrets,512MiB memory=swap,1CPU,PID128,tmpfs64MiB. Fixed workspace UUID path only; existing quota helper independently verifies mountUUID/prjquota/project/ownership and uses its existing exact read-only loop mapping, never given to sandbox.

Prepare succeeds only after bounded real sandbox fixed canary and host/guest same-data hash verification. File helper is fixed image code, uses dir_fd/O_NOFOLLOW per component and regular-file/no-hardlink checks; rejects absolute/.. /backslash/NUL/symlink/device paths. Operations are fixed READ/WRITE/LIST, accepted only under scoped use lease. No arbitrary host command, shell script, path mount or runtime args in HTTP. Private test-only probes are enumerated Python666/NodeCrossRead/failure/cancellation fixtures. This is not production ToolBase registration, file history or object assets.

## Completion, cancellation and idle
Each use owns a durable ID/gen/fence. Runner revalidates before effects and result commit; bounded liveness watcher denies new work and stops exact sandbox when authority/DB unavailable. execCreate/execStart/inspectExec;120s total timeout, stdout+stderr64KiB bounded/truncated, no unbounded queue. Future/callback/HTTP close alone is not stopped. Stop exact container, verify exec/container non-running and callbacks/timers terminated; missing/unreachable inspect is not proof. Uncertain stop retains slot/use and BLOCKED until exact trusted host stop evidence. Idle60 with no active use persists STOP via outbox, stores stop receipt then frees slot/removes exact stopped container; files/project quota retained.

## UI and acceptance
Three public endpoints prepare/get/retry only. Detail distinguishes storage/environment, stable error/actions, READY idle-release explanation; no terminal/file/upload/wake/delete. Real browser through actual API; native positive via private SSH tunnel with newly locally generated fixture credentials, no production credential export. Initial cap2016 services +512sandbox+128runtime+64helper=2720MiB; two-consumer profile stops API/gateway first, remains<=2887. Host>=768MiB/free root>=5GiB; all operator resources counted and builds serial. Read existing operations lessons before execution, fixed scripts before long observation, separate raw failure records. Cloud tests use independent root/DB/XFS/network and bounded finally/watchdog; restore exact R2 V9 and legacy stopped.

## R3.2维护前磁盘准入
只读现场根盘9,225,768,960字节，不能再实分配4GiB后保持5GiB余量。仅可对已卸载/loop脱离的确切R3.1测试XFS做无损冷归档：锁定运维锁、核验路径/UUID/停机身份，流式压缩并逐字节SHA校验两份保护副本，记录原所有权/模式及恢复命令后才释放原预分配文件。旧测试数据保留可恢复，Docker卷/镜像、生产XFS/数据库和旧平台不动，无全局清理/稀疏冒充/复用旧数据；新R3.2仍独立4GiB实分配和UUID。任何守卫或准入不满足即停止云端窗口，继续独立本地工作。

## Fixed file transport framing
The protected bridge uses one UTF8 JSONL frame with newline, at most64KiB. docker-java streaming is not assumed to half-close stdin. Missing terminator and oversized frames are refused; no arbitrary program/endpoint is added. Policy identity is bridge-v2-jsonl, so old inputs are not hot-reused.

## Detailed control-plane decisions before V11 implementation
- Environment physical identity distinguishes immutable creationCommandId/creationFence from the current command/use fence. Container labels bind creation identity; every new use/stop has an independent durable command/use identity and current DB fence. Do not overwrite container identity to match a new use.
- Public POST accepts absent body or empty object only. Its idempotency hash binds action/workspace/If-Match; lookup of a repeated original request precedes current-version rejection. A202 acknowledgement holds the original stable operationId separately from the current environment projection. GET absent environment returns revision0 without writes.
- Extend the existing actor authorization function pattern and existing managed CachingConnectionFactory; environment queue is a separate versioned routing binding on that same factory. No second datasource/factory/scheduler or hand-built AMQP channel manager.
- Prepare/use commit requires live authority. STOP is strictly privilege-reducing system cleanup: an actor becoming inactive must not prevent stopping the exact previously owned container. Stop still requires current ownership/generation/command fence and exact physical identity, with initiator kind SYSTEM distinguished from the originating actor; no fake administrator/task identity.
- READY admission needs a durable startup canary fact, not only running inspect. The final image will run a fixed startup entrypoint before idle, write a command-bound canary with no-follow/exclusive semantics, fsync/read it, and emit a bounded main-process Docker-log receipt. A read-only quota verifier confirms the same guest-written bytes/project from the trusted host view. Log/hash/inspect identities are accepted before any private use. This makes response-loss reconciliation queryable without replaying a canary exec whose output stream was lost. User code is not admitted before that committed boundary.
- The future startup canary is a new policy/image identity and needs full affected native regression; the standalone feasibility source remains separately identified. Docker exec outputs are not assumed retrievable from container logs; record execId before start, capture bounded results durably before returning. Unknown operation results remain unknown rather than replaying file writes.
- Idle/revoke cleanup writes a STOP outbox operation. While stopping, the projection shows an active STOP phase and no allowed action; do not call it executable readiness. Slot release/removal follows an exact committed stop receipt; expired ownership or absent Docker objects alone are insufficient. Completed prepare lease expiry does not itself evict a READY environment; active use has its own exclusive renewable lease.
- An internal operation returns a small signed result identity/hash. Bounded stdout/file-read payloads belong to its scoped immutable result record, not a second file store; they are not streamed as unbounded control-plane responses and do not imply file-version/object-asset delivery.

## Internal v2 routing and transport reuse
Environment management uses fixed `POST /internal/operations/v2/environments` and `GET /internal/operations/v2/environments/{operationId}` beneath the existing runner resource-server chain. The original PROVISION routes remain unchanged. The worker reuses the existing signed runner client's bounded JDK HTTP transport, pinned origin, key pair and signature verifier, rather than creating another connection pool. The signed raw body carries protocol/kind/environment/policy/creation identity; method/path/command/operation/space/workspace/generation/fence and its SHA256 are verified before any lookup or effect. Query derives the original command from the scoped durable operation; it does not create/start a container. Internal response receipts remain below16KiB and are independently signed.

## Runner process identity before enabling data-plane effects
Worker ownership and runner process identity are distinct. V11 also records a runner-instance UUID with its exact Docker container/config/start identity, binds command acceptance and each private use to that instance before effects, and records which instance produced a receipt. A new process's empty in-memory callback map is never evidence that old callbacks exited. The trusted runner obtains its own container identity through docker-java; a new runtime object generates a new UUID, with one registered instance per container start. No API/worker Docker socket or fake task relation is introduced.

An unresolved command/use accepted by another runner instance requires a verified host stop proof for that exact instance before replacement-process reconciliation can attest callback termination. The independent offline host key remains available only to the protected operator, never the API/worker/runner. Standard JCA HMAC verification follows the existing stopped-owner proof format pattern but uses typed workspace/environment/runner fields and its own V11 tables, not fake task/attempt IDs or the chat stop-proof table. Host proof alone does not assert sandbox termination; the replacement runner must still inspect and stop the exact sandbox. Proof import validates container/config/start tuple, fresh observation and chronology; it does not transfer the worker/use owner. A still-authorized existing worker may query its original command through a replacement runner after that proof. Replacing a worker/use owner separately requires expiry and an explicit fenced cleanup handoff. Proof grants query/cleanup convergence only, never create/start/replay of unknown data effects. Unproven owners remain BLOCKED with the slot retained.

The proof importer is a non-web standalone `workspace-environment-ops` profile with an explicit ops flag and Flyway disabled. It refuses combination with API/worker/runner/chat/production profiles and reads only bounded private POSIX files. The256MiB operator is temporary: stop the384MiB API and32MiB gateway before using it alongside an active sandbox so all caps remain under2887MiB. Quota verification has one fail-fast in-process helper slot and detects an unresolved running verifier for the same root across restarts; an uncertain helper does not free that allowance. No concurrent query is allowed to silently create a second64MiB verifier.

## Private data-use implementation contract
- File/probe uses have their own persisted operation UUID and signed HTTP scope, not a fabricated task or lifecycle command. They are enabled only by a protected fixture/operator profile against an explicitly isolated R32 database/root/actor allowlist. No public file/program endpoint or model Toolkit registration is added. MQ remains the lifecycle handoff; a private use performs short admission/claim transactions, one signed runner POST and original-use queries thereafter.
- Each use freezes the immutable container creation identity separately from its own current owner/fence. Claiming a new use increments the environment fence and version, reserves its one unresolved-use row, binds runner before effects and records exact execId before execStart. The original PREPARE operation/fence is historical; idle STOP compares the current environment fence rather than assuming it equals that original command. Lock order remains sandbox slot→workspace→environment→use/result.
- Execution is bounded to120seconds from use admission. A separate15second control-only grace permits actual stop confirmation and terminal receipt persistence; it never permits a new exec, retry, file write or ordinary result after the execution deadline. Renewals use DB time and cannot extend the fixed control deadline. Missing/expired owner or UNKNOWN use retains exclusivity and capacity.
- Ordinary results require live permission, current generation/use fence/owner/lease and matching registered runner. Privilege-reducing stop persistence may ignore actor revocation but cannot impersonate a new owner, bypass a fence or fabricate callback completion. Failed/unknown response is queried without replay. A replacement runner needs old-instance host evidence before claiming old callbacks ended. A known stopped container/use still retains UNKNOWN outcome where original file/exec results are unknown.
- Bounded stdout/file-read payload belongs to a scoped immutable use result with hash, separate from small signed control receipts. The app reads that projection through its protected application port and verifies exit0/content/hash. XFS remains file authority; the result is not an asset/history/version store. A committed stop fact precedes container removal and global slot release; normal idle cleanup refuses an unresolved use. Expired use cleanup requires exact stop/host evidence and a fresh fenced system cleanup, never lease expiry alone.
- The runner writes bounded immutable use facts; the control process alone applies canonical environment/use completion. Emergency termination is immediate in the active runner, outside a DB transaction. Its later system stop record has `effect_origin=USE_TERMINATION` and the real sourceUseId; it does not fabricate a dispatched lifecycle command, inbox or task. Normal PREPARE/idle STOP retain the MQ command path. A fresh system cleanup based on a verified stop fact may close an expired use, but cannot commit an ordinary output, change file facts or execute anything. Old owner/fence stays historical and unknown result state is retained independently from proven STOPPED execution state.
- Ordinary output becomes an authoritative immutable result only under the live execution/runner/authorization guard. Delayed control projection may consume that already committed, matching final fact as non-executing convergence; it cannot create an output or reuse expired execution permission. Stop-only observations use an explicit SYSTEM_STOP writer identity and are permitted after cancellation/expiry solely for the same still-fenced generation and a verified original runner/host-proof chain. They contain no successful ordinary output. Canonical stop convergence then creates a fresh completed system fact operation, preserves the original owner history and releases only the sandbox slot, never the workspace quota/data. Signed management responses return only result identity/hash; payload retrieval remains an authorized app port.
- If a POST never reached durable runner acceptance, query may atomically bind an active stop observer only while both runner and exec identities are absent. This consumes the one acceptance right: a late POST sees an already accepted use and must not execute. This is a stop-only claim under the unchanged generation/fence, not a transfer of the execution owner or a new request. Once any original runner was bound, its precise identity/host-proof requirements remain mandatory. Queries do not attest termination while the original local invocation is still in flight.
- The non-web `workspace-environment-fixture` process requires its explicit fixture flag, a private POSIX scope file and a matching read-only `pf_runtime.workspace_environment_fixture_scope` marker installed only by the isolated test bootstrap (not V11). The marker binds fixture id, actor/space/workspace and frozen policy; current database must be `environment_test` at migration11. It refuses production/identity/chat/API/worker/runner/operator profile combinations. Its fixed roundtrip/readback/output-bound/cancellation programs accept no file path, user script or Docker argument. Reports contain command/use identities and hashes, never raw file payloads or credentials. It uses the worker role and the existing signed client without a Docker socket or provider key. Its transient memory is counted in admission.
- Actual process-window acceptance reuses the existing explicitly scoped fixture barrier, extended with a pure Java effect-boundary port and a fixed R32 point allowlist. It requires `workspace-fixture` plus stage `r32` and refuses production profiles; default composition is a no-op. Points cover claim transaction/commit/ACK, runner acceptance, Docker before-create/created-before-start/started-before-readiness, readiness/receipt, and use output/result boundaries. The host observes a fixed marker then kills only the inventoried test process; no public command can select a barrier. An immutable result already stored in DB may be projected after an HTTP loss even if runner is down; this is convergence, not a database execution fallback.
- Isolation acceptance adds only fixed CPU/PID/memory/network/tmp/byte-quota/inode-quota/path-race probe enums backed by an image-bundled fixed program. They use the same persisted use/exec/termination path and120second bound, not a user script input. Destructive quota probes clean only their own exclusive fixed test artifacts in the newly isolated workspace. OOM that ends the exact sandbox requires a stop fact and cannot leave it advertised READY; host inspect/resource samples corroborate the observed failure independently from guest output. No probe result by itself claims gVisor identity or higher concurrency.
- Desktop runner self-inspection uses structured Compose bind mounts for host files. A Windows drive-letter source in a short `HostConfig.Binds` string cannot be parsed by docker-java3.7.1. Merely spelling long YAML syntax is insufficient when Compose normalizes it back to legacy binds: set `bind.create_host_path=false` and inspect the created container's actual `HostConfig.Mounts` before starting the JVM. Preserve the exact source/target/read-only policy without a third-party fork. This is a deployment-config correction only: retain the already built source242c333 images, bind the corrected config's own Git/blob hash separately, and require unchanged backend/frontend trees before reusing those artifacts.
- Local bootstrap confirmed an operator cgroup OOM at256MiB during the unchanged Argon2 provisioning/recheck path. Adjust only that temporary migration/account operator to320MiB; dependencies+bootstrap total1152MiB, or2624MiB with sandbox scenario after API/gateway stop. The data-use fixture remains256MiB. Do not lower password parameters or use swap. Bootstrap first reads the exact existing identity_operation/user/space facts before deciding whether provisioning is needed; repeated startup is not a reason to repeat completed expensive operations. Runner registration/process startup must pass before starting API/gateway and waiting for their health.
