# Approved architecture

## Control authority
WorkspaceApplicationService coordinates typed WorkspaceRepository and TransactionTemplate. Infrastructure owns Mapper/PO/XML; domain remains pure Java. Store scoped workspace, operation, runner command/receipt, lifecycle lease and physical capacity reservation. Unique(space,actor,idempotency key) plus request hash prevents changed-body replay. A singleton capacity row serializes one2GiB/100000inode reservation in a4GiB mount; failed ambiguous provisioning retains it. State PROVISIONING -> READY/ERROR/BLOCKED. Environment is always NOT_CREATED in this stage. Transitions and workspace.state_changed events commit atomically.

## Reliable orchestration
Create atomically writes workspace/operation/reservation/outbox. Mandatory correlated publisher confirms and returns gate published state. MANUAL ACK follows committed inbox/lease claim. Lifecycle command lease60s/renew10s uses DB time, monotonic generation/fence and live user/membership checks. The sole lifecycle lane is separate from the existing single business execution slot. Lost HTTP responses query the stable operation before any new effect. UNKNOWN neither retries nor releases capacity. Explicit retry requires ERROR, version match, no unresolved owner/effect and fresh current authorization.

## HTTP signatures
Runner-only internal network and no published port. POST /internal/operations and GET /internal/operations/{id}. Spring Security Resource Server with Nimbus RS256; independently pinned control and runner public keys/kid, separate private files, no remote discovery. TTL60s with maximum5s skew. Bind issuer/audience/iat/nbf/exp/jti, method, exact path, raw UTF8 body SHA256, operation/command/workspace/generation/fence. Signed responses bind request identity and response bytes/revision. Reject wrong algorithm/issuer/audience/key/expired body mismatch before effects. Persist nonce and command hash; repeated identical command yields existing operation, changed identity/body rejects. No model credentials or SDK state access for runner. Authorization facts are read with a dedicated narrowly granted role.

## Filesystem and mature adapters
Only runner resolves UUID-derived fixed-root paths. docker-java3.7.1 core+transport-httpclient5 handles Engine calls; no hand-written HTTP or user-provided Docker arguments. A fixed immutable no-network quota-helper image receives only platform IDs and bounded limits; necessary SYS_ADMIN is helper-only, never API/worker/user sandbox. Validate XFS target/UUID/prjquota, no symlink traversal, project ownership and native write refusal. Docker effects are reconciled against durable commands, never treated as a DB distributed transaction. An existing matching directory/project is reconciled; unknown orphan is not deleted. Filesystem READY never starts a business sandbox.

## Delivery and scope
Public endpoints are POST/GET /api/v1/workspaces, GET /api/v1/workspaces/{id}, POST /api/v1/workspaces/{id}/retry. DTO validation, existing session/Origin/CSRF, idempotency and If-Match apply. Pagination is scoped; no admin content bypass. Vue Query polls pending resources, clears on logout and exposes no shell/file/delete/wake controls. Existing chat retains workspaceId=null. Local test project is agentplatform-r31-local. Cloud uses a separate test stack/root/XFS only in an authorized serial window; no local fixture import into production. Resource caps<=2887MiB and hostreserve>=768MiB; current fixture API512, two workers512 each, PG320, MQ512, runner384 and gateway32 total2784MiB; one transient helper64 brings the limit total to2848MiB. The initial runner256MiB observation OOM is retained; this allowed budget revision restarts the full1800second clock. The heap stays112MiB and no swap is added. Stop test API/workers before512MiB canary plus128MiB runtime. Root free>=5GiB. Real supplier calls0. R2 production restored after every cloud window.

## Implementation clarifications
Workspace events alone permit conversationId=null; existing chat event types still require a conversation identity. Workspace event facts are persisted in the scoped workspace ledger, and the UI polls the authoritative resource.

docker-java3.7.1 dependencies converge at commons-compress1.28.0, commons-io2.21.0 and BouncyCastle1.83; existing application/SDK/Jackson baselines remain unchanged. Standalone workspace processes use one managed AMQP connection factory and no model key. When combined with chat profiles they reuse the existing connection factory.

A fixed retained helper container is bound to the command IDs, image config and mount. A query may inspect its completed result without starting it again. Unknown pre-existing directories are never classified as NOT_STARTED. Helper containers are not auto-removed before durable result reconciliation.

Expired active lifecycle operations are conservatively marked UNKNOWN/BLOCKED by a trusted transactional sweep under capacity -> workspace -> operation locks and database time. It retains owner/fence, reservation and directory, does not prove termination, free capacity, reassign ownership or invoke runner. The expired worker itself remains unable to write. This prevents indefinitely showing PROVISIONING after process loss without weakening stop semantics.

Live authorization uses the established PostgreSQL SECURITY DEFINER pattern with fixed search_path, typed actor/space arguments and revoked PUBLIC execution. It takes SHARE locks on the user, membership and storage-policy rows inside the short transaction, so concurrent disable/revoke/freeze is ordered with commit rather than an unlocked EXISTS check. The dedicated runner receives EXECUTE on this boolean function, not direct identity-table privileges.

Actual process-crash acceptance reuses the existing host-driven fixture-barrier pattern. A nonempty barrier requires both workspace-fixture profile and explicit r31 stage, rejects production/HTTP deployment profiles, accepts only fixed claim-before-commit, claim-after-commit-before-ack, ack-before-runner and helper-exited-before-receipt points, and writes a constant private /tmp marker before waiting for the trusted host to kill that exact container. The normal composition is a no-op and no public endpoint controls barriers. Before-commit process loss must roll back the complete claim before redelivery; committed worker-loss windows must retain ownership/capacity and never replay merely on lease expiry. The helper-exit window must recover through signed GET/inspect only, with original command/generation/fence and one Docker create event.
# Operational topology is an explicit deployment input

The control plane uses vhost `/agentplatform`, durable direct exchange `ap.workspace.commands.v1`, queue `ap.workspace.provision.v1` and binding `workspace.provision`. Import `deploy/config/r3-workspace-mq-topology.json` through the existing protected RabbitMQ definitions process, adding the environment-specific user/permissions outside Git. The framework adapter does not assume a Spring RabbitAdmin will manufacture topology. A broker ping is insufficient: acceptance checks the actual vhost, exchange, queue and binding before starting producers/consumers. This does not add another dispatch path.

## Verified loop device for native quota

The trusted operator attaches the independent preallocated image, verifies backing file and filesystem UUID, and pins the resulting `/dev/loopN` for the window. Runner accepts only that restricted configuration path. docker-java maps that one exact device to the same container path with permission `r`; no raw-device write/mknod grant, wildcard, new capability or device exposure to API/worker/user sandbox is allowed. Helper verifies XFS target/UUID first, then that mount source is a non-symlink loop block node whose `st_rdev` matches the mounted root `st_dev`, before native quota queries or any allocation. Inspect/reconciliation also checks the exact device mapping. Missing/wrong device refuses before effects; the Desktop no-XFS profile can leave the optional reference empty but cannot produce READY. Native remounts retain the same attached test loop identity; cleanup detaches only that verified backing file after unmount. Never change the original production loop/UUID.
