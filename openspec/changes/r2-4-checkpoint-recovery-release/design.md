## Safe points and SDK composition
Checkpoint v2 phases INPUT_READY, MODEL_COMMITTED, TOOL_COMMITTED and TERMINAL. INPUT_READY freezes complete authorized input before any physical call and permits zero committed rounds with a real SDK state clone. An immutable draft is serialized outside locks, then current-watermark/owner authorization, SDK state CAS and checkpoint insertion commit in one short transaction. No untracked save/seal gap.

The existing public state APIs and narrow clone adapter are retained for the SDK loadedVersion limitation. Restoring uses Request.restoring=true, empty caller input, checkpoint recoveryHistory and an independent attempt state namespace. nextTurn and logical identity are task-wide. Successful tool observations restore FINISHED state without re-execution; a new PREPARED test operation requires a binding to the current attempt before RUNNING. Production tool catalog is empty; deterministic profile has a fixed catalog and no real-provider access. All profiles share the same durable execution pipeline.

## Qualification, accounting and races
Latest stop receipt must match source attempt/owner/fence; proof validation remains exact-container/image/start-time plus expired lease. For new recoverable checkpoints stopped-owner convergence records blocked/eligible facts without automatic dispatch. Legacy unsent/no-checkpoint requeue and committed-final safe convergence remain explicit compatibility paths.

Reject cancelled/succeeded tasks for continuation, revoked identities/credentials/models, any unresolved model/tool UNKNOWN, incompatible/missing/hash-bad state, ledger advanced beyond snapshot, or later independent conversation tasks. Terminal facts only converge without calls. Duplicate command hashes return the same result; different bodies with the same commandId conflict; competing versions cannot create two generations. Claim revalidates qualification and versions, state-copy failure rolls back without ACK. Cancellation and revocation obey the same lock order and precommit guards.

120seconds starts at first execution and is database-persisted; restart never resets it. Four physical calls/retry/empty-repair allowances are task-wide. Only unused remaining allowance is atomically reserved after prior release; consumed/UNKNOWN facts are never cleared. If deadline expires while queued, fail without a call. New bundle rejects hot-restoring old bundle state; old fixtures remain readable through explicit legacy adapters.
